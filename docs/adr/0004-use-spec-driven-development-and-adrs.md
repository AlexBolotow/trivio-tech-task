# ADR-0004: Use Spec-Driven Development and ADRs

- Status: Accepted
- Date: 2026-09-25

## Context

Основную реализацию выполняет AI, а пользователь утверждает требования, архитектурные решения и результат. Одного ревью готового кода недостаточно: предположения о поведении должны быть видимы до реализации.

## Decision

Для нетривиальных изменений использовать облегчённый Spec-Driven Development: `proposal → specification → design → tasks → implementation → verification`. Долгоживущие архитектурные решения фиксировать отдельными ADR.

## Alternatives

- Работать только по сообщениям в чате.
- Документировать решения после реализации.
- Использовать полный обязательный change-пакет для любого изменения.

## Consequences

- Пользователь утверждает смысл и компромиссы до появления кода.
- После сжатия контекста у агента остаётся проверяемый источник намерений.
- Появляются дополнительные Markdown-артефакты, поэтому процесс применяется пропорционально риску изменения.
