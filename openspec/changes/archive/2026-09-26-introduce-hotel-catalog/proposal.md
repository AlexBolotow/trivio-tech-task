# Proposal: Introduce hotel catalog

- Status: Accepted
- Created: 2026-09-25

## Why

Проекту нужен первый бизнесовый вертикальный срез, который покажет базовый Laravel HTTP flow и создаст каноническую основу для будущих импорта, сопоставления, поиска предложений и бронирования.

Каталог отвечает за стабильные сведения об отелях и типах номеров. Он не должен смешиваться с актуальной ценой и доступностью: эти данные зависят от дат, состава гостей и состояния поставщика.

## What changes

- Появляется модуль `Catalog`, организованный по бизнесовой функции.
- Добавляются минимальные MySQL-таблицы городов, канонических отелей, типов номеров и фотографий типов номеров.
- Добавляются Eloquent-модели, фабрики и демонстрационный seeder для локального окружения.
- Добавляется read-only endpoint `GET /api/v1/catalog/hotels` с фильтром по городу и пагинацией.
- Ответ содержит только стабильные каталожные данные и не заявляет цену или доступность.
- Поведение закрепляется HTTP feature- и database integration-тестами.

## Scope

- Активные канонические отели одного города.
- Активные канонические типы номеров и их фотографии.
- Предсказуемая пагинация.
- Публичный JSON-контракт через Laravel API Resources/read DTO.
- MySQL как источник истины.

## Non-goals

- Импорт дампов поставщиков и staging-таблицы.
- Сопоставление одинаковых отелей и типов номеров между поставщиками.
- Цены, availability, offers и `price_from`.
- Вызовы API поставщиков.
- Elasticsearch, Redis, RabbitMQ и фоновые jobs.
- Создание и редактирование каталога через HTTP.
- Бронирование, авторизация и административный интерфейс.

## Product clarification

Endpoint этого изменения намеренно называется `/api/v1/catalog/hotels`, а не `/api/v1/hotels`. Он показывает только канонический статический каталог и не является финальной реализацией заданного поиска доступных отелей. Финальный поисковый endpoint будет спроектирован отдельно и потребует дат поездки, состава гостей и оркестрации поставщиков.
